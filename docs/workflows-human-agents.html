Two workflows: the person and the agents

The same product seen from two sides. The person works in the first diagram. The agents and code checks work in the second, inside the Assess step.

The idea: the agents propose, the code verifies, the human decides.

1. Human workflow

What the project manager does, step by step. Nothing here asks a model anything except the Assess click.

sequenceDiagram
    autonumber
    actor PM as PM
    participant UI as Screens
    participant API as Backend
    participant DB as Database
    PM->>UI: Sign in (simulated)
    UI->>API: Create session
    PM->>UI: Create project and subcontractor
    UI->>API: Save
    API->>DB: Insert
    PM->>UI: Drop PDFs, tick what each is for
    UI->>API: Upload
    API-->>UI: Per-file result, warnings
    PM->>UI: Click Assess
    Note over UI,API: Agents work here (see the other diagram)
    API-->>UI: Progress, then findings
    PM->>UI: Open a finding
    UI->>API: Get quote and page text
    API-->>UI: Redacted text, quote highlighted
    PM->>UI: Decide (confirm or change, reason)
    UI->>API: Save decision
    alt not signed in
        API-->>UI: 401
    else reason missing
        API-->>UI: 422, say what is missing
    else valid
        API->>DB: Append to decision log
        opt ask for new upload
            API->>DB: Append simulated email draft
        end
        API-->>UI: Updated finding
    end
    PM->>UI: Open overview and summary
    UI->>API: Get overview
    API-->>UI: Statuses and counts, no scores
  • Sign-in and the email draft are simulated. Nothing is sent.
  • The PM sees three separate statuses: what the model said, what the checks left, and the PM's own decision.
  • Every decision is appended to a log. It is never edited.

2. Agentic workflow

What happens behind one click on Assess. It repeats for every requirement.

sequenceDiagram
    autonumber
    participant API as Backend
    participant Orch as Orchestrator
    participant Chk as Code checks
    participant Prov as Provider
    participant LLM as Assessor model
    participant Ver as Verifier agent
    loop each requirement in the template
        API->>API: Pick documents (tagged plus untagged)
        alt no document applies
            API->>API: Record No document, No model call
        else documents exist
            API->>Orch: Assess requirement
            Orch->>Prov: Prompt with untrusted text between markers
            Prov->>LLM: Request, no tools
            LLM-->>Prov: JSON answer
            Prov-->>Orch: Answer
            alt invalid against schema
                Orch->>Prov: Retry once
                Prov-->>Orch: Answer
                opt still invalid
                    Orch-->>API: Needs human review plus note
                end
            end
            Orch->>Chk: Check quotes on cited pages, dates
            Chk-->>Orch: Automatic status (can only be weaker)
            opt verifier on, status found or partial
                Orch->>Ver: Requirement plus verified quotes
                Ver-->>Orch: Supports yes or no
                Note over Orch,Ver: No lowers to Needs human review
            end
            Orch-->>API: Result with provider label
        end
    end
    alt provider error
        API-->>API: Stop, save nothing, return 503
    else all done
        API->>API: Save one finding per requirement
    end
PartMay doMay not do
Assessor modelPropose a status and quotesUse tools. Its answer only counts as validated data.
Code checksVerify quotes, check datesRaise a status
Verifier agentJudge if the quotes support the requirementRaise a status
  • A requirement with no document never reaches a model.
  • Document text is untrusted. It sits between random markers and the prompt says to ignore instructions inside it.
  • Found or partial needs a quote that exists on the cited page, or it becomes Needs human review.
